### Module pattern (every feature module follows this)

```
<module-name>/
  <module-name>.module.ts        # NestJS @Module declaration
  <module-name>.controller.ts    # route handlers only, no business logic
  <module-name>.service.ts       # business logic, calls Prisma
  dto/
    create-<entity>.dto.ts       # Zod schema + inferred type
    update-<entity>.dto.ts
    <entity>-response.dto.ts     # shape returned to client
    <entity>-query.dto.ts        # query/filter params (if needed)
```

## Key conventions in this tree

- **One module = one directory** on both backend and frontend.
- **DTOs live inside their module**, not in a global `dto/` folder.
- **API layer is separate from query hooks** -- `api/` has raw HTTP calls, `queries/` has TanStack Query wrappers.
- **Stores are flat files** in `stores/`, one per concern.
- **Pages are grouped by feature** in `pages/<feature>/`, components in `components/<feature>/`.
- **No barrel files** (`index.ts` re-exports) except for `components/ui/` -- import directly from the file.
